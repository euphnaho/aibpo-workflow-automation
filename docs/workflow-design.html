Process Design

商談結果報告フロー

Jicoo経由／記名ルールの2つの入口から初回商談を判定し、「案件化 / 検討中 / 失注」の振り分けとNA日の追いかけまでを自動化する設計。

最終更新 2026-08-17（v4）  ·  掲載データはすべてダミー

01

全体フロー

Jicoo経由と手動登録の2つの入口を、GASの一括判定で1本の「初回商談一覧」に合流させる。Slack通知のボタンを押した時点で3方向に分岐し、案件化は既存のSlackワークフローへ、未案件化はNA日を起点にSlack通知へループバックする。

04

Slackワークフロー設定手順

Slack Workflow Builder 側は手動設定。GASからは自動生成できない。Slack通知のボタンは3つあり、それぞれ別のワークフロー（うち1つは既存）へ飛ぶため、「案件化ステータスを質問する」ステップは不要。

4.1　既存の「案件化」ワークフローへの追加設定

案件リストへの書き込みは既存ワークフローがすでに行っているため、そこは変更しない。商談DB（初回商談一覧）を更新するためだけに、末尾へ1ステップ追加する。

  1. リンクトリガーに入力変数 calendar_id を追加
    company_name 等の変数がすでにあれば流用し、無ければ追加する。GASが投稿する「案件化した」ボタンのURLに calendar_id company_name contact_name sales_rep をクエリパラメータとして付与する。
  2. 「Webリクエストを送信」を追加
    GAS Web App の /exec URLへ { secret, calendar_id, company_name, contact_name, sales_rep, status: "案件化した" } をPOSTする。company_name は既存ワークフロー内で営業担当が確定させた値を使う。
  3. その後に「メッセージを送信」を追加
    チャンネルへ完了報告を投稿する（例: 「✅ {{company_name}} を案件化として記録しました」）。GASからは完了報告を行わない。

4.2　新規ワークフロー（進行中／失注）

「進行中（未失注）」「失注した」それぞれに独立したシンプルなワークフローを作る。If/Thenでの分岐は不要（ボタンごとに別ワークフローなので迷わない）。

  1. 進行中（未失注）用ワークフローを作成
    リンクトリガーの入力変数: calendar_id company_name contact_name sales_rep。フォームで企業名・担当者名（編集可）・ネクストアクション・NA日（必須・再通知ループの起点）・案件化見込み度を収集し、Webリクエストで status: "進行中（未失注）" として送信。最後に「メッセージを送信」で完了報告（例: 「📝 {{company_name}} を追いかけ中商談リストに記録しました」）。
  2. 失注した用ワークフローを作成
    リンクトリガーの入力変数は同じ4つ。フォームで企業名・担当者名・失注区分・失注理由（マスター参照）・詳細メモを収集し、Webリクエストで status: "失注した" として送信。最後に「メッセージを送信」で完了報告（例: 「📕 {{company_name}} を失注リストに記録しました」）。
  3. どちらも共有シークレットをJSONボディに含める
    Slack側はカスタムHTTPヘッダーがGAS側で読み取れないため、認証用シークレットはヘッダーではなくJSONボディに含めて渡す。URL・Methodは4.1と同じGAS Web Appの /exec。完了報告はどのワークフローも自身の「メッセージを送信」ステップで行い、GASからは投稿しない。
05

導入マイルストーン（①〜⑧）

番号は次の「06 スケジュール」の日程表と共通。

  • ①「Jicoo対象リスト」を作成する（大さん保有分を転記）
  • ②初回商談一覧・追いかけ中商談リスト・失注リストのシート構成を更新する
  • ③CalendarFetch.gs を配置し、Jicoo判定条件を実データで検証・調整する
  • ④Incoming Webhook URLを確認する（発行済み）
  • ⑤Slack Workflow Builderを設定する：既存の案件化ワークフローへWebリクエスト＋メッセージ送信ステップを追加＋新規「進行中」「失注」ワークフローを作成
  • ⑥gas/ 配下のコードを配置し、3つの時間主導トリガーを設定する
  • ⑦初回ループ・NA日再通知ループの両方をダミーデータでE2Eテストする
  • ⑧チームへ共有・運用開始を案内する

未確定・要相談

  • 既存の案件化ワークフローの管理者との調整が必要。calendar_id 入力変数の追加と「Webリクエストを送信」ステップの追加を編集権限を持つ人に依頼し、既存ワークフロー内で企業名を確定しているフィールド名も確認して company_name に合わせる。
  • Jicoo経由かどうかの判定方法が仮実装。予定の説明欄/場所欄に "jicoo" という文字列が含まれるかで判定しているが、実際のJicoo連携でこの情報が入るか未検証。入らない場合は r_jicoo シートのような既存データとカレンダーIDを突き合わせる方式に差し替える必要がある。
  • 失注理由の選択肢（マスターシート記載分）をSlackワークフロー側へ転記する作業は手動。
  • 追いかけ中商談リストの行は物理削除せず残す設計のため、長期運用で行数が増え続ける。四半期単位のアーカイブ運用を別途検討する。
